AI Job Application Agent

A human-in-the-loop application system that helps a job seeker discover opportunities, evaluate fit, create evidence-based application materials, and maintain an auditable approval process.

Python, SQLite, StreamlitPrimary tools
Product design and implementationMy role
Working prototypeStatus

The challenge

Job searching involves repeated work across multiple disconnected steps: collecting postings, removing duplicates, judging fit, tailoring application documents, checking factual accuracy, and tracking outcomes. Fully automating this process also creates risk because an agent can overstate qualifications or act without adequate review.

The solution

I designed a modular Python workflow that separates opportunity discovery from application approval. Each job passes through normalization, deduplication, fit scoring, packet generation, factual verification, and a final human approval gate.

The central design principle is simple: AI can prepare and validate the work, but the user remains responsible for approving any external action.

Engineering decisions

  • Used a CLI-first structure so each workflow stage can be tested independently.
  • Stored normalized job, score, packet, and status information in SQLite.
  • Separated configuration from code for approved domains and scoring rules.
  • Added safe failure behavior when factual verification or approval requirements are not met.
  • Used Streamlit as a lightweight review and tracking interface.

Validation and safeguards

  • Unit tests for daily automation and core workflow behavior.
  • Explicit allowlists for supported application domains.
  • No automatic submission without a verified and approved packet.
  • No credentials, private résumé files, or real application history in the public version.

Outcome and next steps

The prototype demonstrates a complete, controlled workflow rather than a collection of disconnected AI prompts. The next public release will use fictional job postings and a synthetic candidate profile, followed by stronger score explainability, dashboard screenshots, and CI-based test execution.

Confidentiality

This public case study uses generalized business logic and synthetic examples. It does not include confidential employer data, proprietary code, credentials, customer information, or internal documentation.
